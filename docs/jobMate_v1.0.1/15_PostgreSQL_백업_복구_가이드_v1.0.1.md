## 1. 백업 대상

조직·사용자·workflow, 실행·감사 이력, Gmail cursor, Calendar event link, 푸시 구독과 outbox 상태를 포함한다. OAuth 암호화 키는 DB 백업과 별도로 접근 통제된 비밀 저장소에 백업한다.

## 2. 운영 원칙

- 암호화된 자동 백업과 보존 기간을 운영자가 설정한다.
- 복구 목표(RPO/RTO)는 서비스 배포 환경과 파일럿 조직의 합의로 정한다.
- 백업 파일 접근 및 복구 작업을 감사 기록에 남긴다.
- 복구 전 외부 Google/Push 작업 큐를 중지해 재실행으로 생길 부작용을 방지한다.

## 3. 복구 후 확인

1. DB schema/migration 상태를 확인한다.
2. 외부 작업 큐를 멈춘 채 run/event link 및 idempotency 상태를 점검한다.
3. OAuth 연결 상태를 재검증하고 필요하면 재인증을 요구한다.
4. Calendar와 DB event ID를 대조해 중복 등록 없이 outbox를 재개한다.
5. 알림과 감사 조회가 가능한지 확인하고 복구 시각을 기록한다.

실제 명령과 보존값은 선택한 PostgreSQL 운영 서비스의 승인된 runbook에 별도로 기입한다.
