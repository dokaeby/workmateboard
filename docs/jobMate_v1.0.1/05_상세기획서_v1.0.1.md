## 1. Gmail 연결

관리자는 또는 사용자는 Google 계정 연결을 시작하고 OAuth 동의 화면에서 Gmail 읽기와 Calendar 이벤트 생성에 필요한 범위를 확인한다. 성공 시 계정 이메일, scope, 연결 상태를 표시한다. 연결 해제 시 감지 작업과 예약 푸시 작업을 중단하고 토큰을 폐기한다.

수용 기준: 사용자가 동의하지 않으면 연결되지 않는다. scope 부족이나 철회는 연결 오류로 분명히 표시된다.

## 2. Gmail 일정 자동 등록

### 사용자 흐름

1. 사용자가 연결한 Google 계정에서 일정 메일 자동 감지를 켠다.
2. 시스템이 정해진 주기로 신규/변경 메일을 검색한다.
3. 에이전트가 일정 후보를 만들고 검증한다.
4. 검증 통과 일정은 Google Calendar에 자동 등록된다.
5. jobMate가 사용자에게 웹 푸시를 보낸다.
6. 사용자가 푸시를 선택하면 원본 Gmail 메일이 열린다.

### 사용자 설정

- 자동 감지 켜기/끄기
- Google 연결 계정 및 연결 상태 확인
- 감지 마지막 실행 시각과 처리 결과 확인
- 웹 푸시 허용, 앱 내 알림 확인

### 자동 등록 정책

일정 시작/종료 시각을 확정할 수 있는 메일만 자동 등록한다. 날짜만 있고 시각이 없는 종일 일정은 원문이 명확히 종일임을 표현하는 경우 all-day 이벤트로 생성한다. 상대 날짜(예: 다음 주 화요일)는 메일 발송일과 계정 시간대를 기준으로 해석한다. 해석이 여러 가지인 경우 보류한다. 반복 일정은 MVP에서 자동 생성하지 않고 검토함으로 보낸다.

## 3. 푸시 알림 UX

푸시 제목은 일정 제목 또는 일반 알림으로 표시하고 본문은 “메일에서 일정이 캘린더에 추가되었습니다” 수준으로 제한한다. 알림을 탭하면 원본 메일 URL로 이동한다. 앱이 열려 있으면 해당 원본 메일 링크를 새 탭으로 열며, 인증이 필요하면 Google 로그인으로 이어진다. 허용되지 않은 리다이렉트 URL은 거부한다.

수용 기준: 푸시 권한 거부 상태에서도 자동 등록이 중단되지 않고 앱 내 알림이 생성된다. 클릭 이벤트는 해당 알림과 원본 메시지 식별자에 연결된다.

## 4. 문서 업무

회의록 정리, 문의 답변 초안, 주간 보고서 템플릿은 공통 실행 목록/상세 화면을 사용한다. 사용자는 입력과 파일을 제출하고 진행 상태, 최종 결과, 실패 단계를 확인한다. 외부 메일 발송과 고위험 변경은 MVP에서 실행하지 않는다.

## 5. 관리·감사

관리자는 템플릿 버전을 발행하고 연결 정책을 설정한다. 감사 이력에는 계정 연결·해제, 자동화 활성화, Calendar 생성, 승인 결정과 설정 변경의 행위자·시간·대상 ID를 기록한다. 메일 본문과 OAuth 토큰은 감사 이력에 넣지 않는다.
