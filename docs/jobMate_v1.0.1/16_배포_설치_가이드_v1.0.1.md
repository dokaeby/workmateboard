## 1. 환경 설정

환경별 설정으로 Django secret, PostgreSQL DSN, queue DSN, LLM provider key, Langfuse key, Google OAuth client credentials, token encryption key, Web Push VAPID key를 주입한다. 비밀값은 저장소에 커밋하거나 컨테이너 이미지에 포함하지 않는다.

## 2. 배포 구성

- 웹/API는 HTTPS에서 제공한다.
- worker는 별도 프로세스로 실행하고 종료 시 진행 중인 작업을 안전하게 반환한다.
- 스케줄러는 사용자별 Gmail polling과 예정 푸시를 큐에 넣는다.
- Service Worker와 manifest는 같은 secure origin에서 제공한다.
- PostgreSQL은 네트워크 접근을 API/worker로 제한하고 자동 백업을 켠다.

## 3. 배포 순서

1. 비밀값과 Google OAuth redirect URI, HTTPS 도메인을 등록한다.
2. DB migration을 적용하고 앱/API를 배포한다.
3. worker·scheduler와 서비스 워커 정적 파일을 배포한다.
4. health/readiness, Langfuse 연결, Google OAuth callback을 확인한다.
5. 내부 sandbox 계정으로 Gmail→Calendar→push→원본 메일 이동을 확인한다.
6. 지정 사용자에게 점진적으로 기능을 활성화한다.

## 4. 롤백

자동 감지 설정을 끄고 scheduler가 새 작업을 만들지 않게 한 뒤 worker를 drain한다. 코드 롤백 후 migration 호환 여부와 이미 생성된 Calendar 이벤트 이력을 확인한다. 외부 생성 이벤트는 무단 삭제하지 않는다.
