## 절차

1. 테스트용 PostgreSQL과 앱·워커를 기동하고 migrations를 적용한다.
2. Google API, LLM, Web Push 테스트 adapter를 구성한다. 별도 sandbox 계정이 준비된 경우에만 외부 API 검증을 수행한다.
3. 조직·사용자·템플릿·OAuth 연결 fixture를 생성한다.
4. 각 통합 케이스를 실행하고 DB 상태, 외부 요청 수, event ID, queue 결과를 함께 확인한다.
5. worker 중단·중복 queue·API timeout을 주입해 복구와 멱등성을 검증한다.
6. 실행 로그와 테스트 환경 설정을 결과에 기록하고 민감 정보가 포함되지 않았는지 확인한다.

통과 기준은 기능별 기대 상태가 PostgreSQL에 일관되게 남고 재시도 후 중복 Calendar 이벤트가 생성되지 않는 것이다.
