## 1. 제품 개요

jobMate는 기업의 반복 업무를 워크플로로 구성하고 각 단계에 전문 에이전트를 할당해 실행·관찰·승인하는 서비스다. 장기 목표는 기업의 모든 업무 자동화이며, MVP는 범위를 통제해 문서 업무 3종과 Gmail 일정 자동화로 효용과 안전성을 검증한다.

## 2. 목표와 비목표

### 2.1 목표

1. 회의록 정리, 문의 답변 초안, 주간 보고서 작성을 에이전트 흐름으로 자동화한다.
2. 사용자가 연결한 Gmail에서 일정 정보를 찾아 Google Calendar에 자동 등록한다.
3. 일정이 등록되면 웹 푸시를 보내고, 푸시를 선택하면 원본 Gmail 메일을 연다.
4. 모든 에이전트 단계, 상태, 오류, 비용과 도구 호출을 추적한다.
5. 권한, OAuth 동의, 중복 방지와 감사 기록으로 기업 사용의 통제성을 제공한다.

### 2.2 비목표

- 임의의 업무를 자연어만으로 무검토 생성하는 범용 빌더
- 급여·결제·계약 등 고위험 업무의 무인 처리
- Gmail 이외의 기업 메일 시스템 및 다양한 업무 시스템 연동
- 에이전트의 임의 코드 실행, 셸 접근, 자체 권한 확대
- 푸시 전달의 보장 또는 일정 변경을 메일에 자동 회신하는 기능

## 3. 사용자 및 핵심 흐름

사용자는 조직 관리자, 업무 요청자, 승인자로 구분한다. 관리자는 템플릿·연동 정책을 관리하고, 요청자는 업무를 실행하며, 승인자는 정해진 업무 결과를 검토한다.

Gmail 일정 자동화는 사용자가 Google 계정을 연결하면 동의된 Gmail 범위를 주기적으로 확인한다. 일정이 들어 있는 메일을 찾으면 에이전트가 날짜·시간·제목·장소를 추출하고 검증해 Calendar에 자동 등록한다. 등록이 완료되면 일정 요약이 포함된 웹 푸시를 보내며, 알림 클릭은 해당 Gmail 원본 메일 URL로 이동한다. 필수 정보가 불명확한 메일은 자동 등록하지 않고 확인 대기함에 둔다.

## 4. MVP 기능 범위

| 기능 ID | 기능 | 핵심 범위 |
|---|---|---|
| JM-AUTH-01 | 조직 및 사용자 | 로그인, 조직 멤버십, 관리자·요청자·승인자 권한 |
| JM-WF-01 | 업무 템플릿 | 회의록, 문의 초안, 주간 보고서 실행 |
| JM-AGENT-01 | 멀티 에이전트 오케스트레이션 | LangGraph 상태 그래프, LangChain 모델·도구, 단계별 결과 저장 |
| JM-GMAIL-01 | Gmail 일정 감지 | 사용자 동의 기반 메일 검색 및 이벤트 정보 추출 |
| JM-CALENDAR-01 | Calendar 자동 등록 | 유효한 일정 자동 생성, 중복 방지, 실패 재처리 |
| JM-PUSH-01 | 일정 웹 푸시 | 일정 등록 직후 알림, 클릭 시 원본 Gmail 메일 이동 |
| JM-OBS-01 | 추적·감사 | Langfuse trace와 실행·도구·사용량 기록 |

## 5. 성공 지표

- 템플릿별 성공 완료율, 사용자 수정률, 업무 절감 시간
- Gmail 일정 추출 정밀도, 자동 등록 성공률, 중복 등록률
- 일정 인식부터 Calendar 등록까지 지연, 푸시 전달·클릭률
- 실행당 토큰·비용, 에이전트 단계별 실패율

파일럿에서 기준선을 측정한 뒤 목표 수치를 확정한다. 자동 등록은 오류율과 중복률을 먼저 확인하고 적용 범위를 점진적으로 넓힌다.

## 6. 보안·개인정보 원칙

- Google OAuth의 최소 권한을 요청하고 연결·철회·삭제를 제공한다.
- Gmail 메일 본문은 에이전트 입력 데이터로만 취급한다. 본문 지시가 도구 권한을 바꾸지 못한다.
- Calendar 등록 도구는 사용자가 활성화한 자동화 정책의 범위에서만 실행한다.
- 이벤트 생성은 외부 부작용이므로 원본 메일 ID와 이벤트 ID로 멱등성을 보장한다.
- 푸시 본문에는 민감한 메일 내용을 넣지 않는다. 클릭하면 Gmail의 원문 URL로 이동하며 Gmail 로그인은 Google이 처리한다.
- OAuth 토큰은 암호화 저장하고 로그·Langfuse에 토큰이나 원문 전체를 남기지 않는다.

## 7. MVP 완료 조건

- 문서 업무 템플릿 3종이 단계 상태와 결과를 제공한다.
- 동의된 Gmail 계정에서 일정 메일을 감지해 유효 이벤트를 Calendar에 자동 등록한다.
- 같은 원본 메일을 재처리해도 중복 이벤트가 생기지 않는다.
- 등록된 일정의 웹 푸시가 발송되고 클릭 시 해당 원본 메일이 열린다.
- 모호하거나 불완전한 일정, 권한 철회, API 실패가 안전한 상태로 처리된다.
- 실행 추적·감사 로그에서 에이전트 단계와 결과를 확인할 수 있다.

## 8. 에이전트 하네스 설계

jobMate의 에이전트는 모델 단독 기능으로 보지 않고, 모델을 둘러싼 실행 환경까지 포함해 설계한다. 목표는 모델이 작업을 완료했다고 말하는 것이 아니라 검증 가능한 증거를 남기며 업무를 끝내는 것이다.

| 계층 | jobMate MVP 적용 | 완료 증거 |
|---|---|---|
| 가이드 | 템플릿별 목적, 입력·출력 계약, 금지 행동, 완료 정의, 에스컬레이션 조건을 버전으로 관리 | 모든 실행이 특정 템플릿/에이전트 버전을 기록 |
| 센서 | JSON schema, 날짜·시간대 검증, 조직 권한, 중복 검사, 링크 허용 목록, 테스트 케이스 등 결정적 검사 우선 | 검증 실패 시 Calendar 쓰기·완료 상태로 진행하지 않음 |
| 에이전틱 루프 | LangGraph에서 계획된 단계만 수행하고 단계·시간·토큰·도구 호출·재시도 상한을 적용 | 예산 소진 시 안전 정지, 부분 결과와 미완료 사유 저장 |
| 메모리 | PostgreSQL에 실행 상태, 체크포인트, 단계 결과, 외부 작업 멱등 키를 지속 저장 | worker 재시작 후 완료 단계를 반복하지 않고 이어서 처리 |
| 권한과 예산 | 조직·사용자별 최소 권한 도구, 별도 Gmail read / Calendar write scope, 비용·시간 제한 | 정책 밖 도구 호출과 조직 간 데이터 접근이 서버에서 차단 |
| 관찰가능성 | Langfuse trace와 업무 DB의 실행·단계·외부 부작용·승인·비용·에스컬레이션 기록 | 실행 ID로 실패 단계, 사용량, 결과 및 Calendar 이벤트를 추적 |

### 8.1 하네스 운영 원칙

- 계산형 검사를 우선 사용한다. LLM judge는 결정적 검사를 대체하지 않고 품질 표본 검토에만 보조적으로 쓴다.
- Gmail 내용과 첨부 텍스트는 비신뢰 데이터다. 그 안의 지시는 도구 권한, 수신 범위, 정책을 변경하지 않는다.
- 명확하고 검증된 일정은 활성화된 자동화 정책에 따라 자동 등록한다. 모호하거나 반복 조건이 불명확한 일정만 사람 검토로 에스컬레이션한다.
- 외부 부작용인 Calendar 생성은 별도 도구 권한, idempotency, 사후 검증과 감사 기록을 갖춰야 한다.
- 작업을 완료로 표기하려면 Calendar event ID 또는 다른 업무 결과의 저장 증거가 있어야 한다.

### 8.2 초기 실행 한도

| 한도 | 초기 제안 | 소진 시 동작 |
|---|---:|---|
| 모델 재시도 | 단계당 최대 2회 | 실패 표시 후 다음 단계 진행 중단 또는 검토 대기 |
| 외부 API 재시도 | 일시 오류에 최대 3회, backoff 적용 | 재시도 대기/실패 큐 |
| 전체 실행 시간 | 업무별 설정, 기본 10분 | 체크포인트 저장 후 안전 정지 |
| Calendar 생성 | 원본 메일당 이벤트 1건 | 중복이면 기존 이벤트 참조 |
| 도구 호출 | 실행당 초기 최대 20회 | 즉시 정지 및 원인 기록 |
| 모델 비용 | 환경 설정 상한 필수, 파일럿 전 금액 확정 | 추가 호출 차단, 부분 결과 반환 |

상한은 제품 기본값 제안이며 실제 비용과 지연 데이터를 통해 파일럿 중 조정한다. 외부 글의 수치를 그대로 적용하지 않는다.

## 9. 실패 개선 래칫

같은 유형의 실패가 발생하면 재현 가능한 입력과 trace를 보존하고, 원인을 가이드 누락·센서 부재·루프 한도·체크포인트·과도한 권한·관찰 공백 중 분류한다. 가장 강한 적합 계층을 수정한 뒤 원 실패 시나리오와 회귀 케이스로 검증한다. 반복된 실패를 프롬프트 문구만 덧붙여 처리하지 않는다.
