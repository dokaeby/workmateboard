## 1. 화면 목록

| 화면 ID | 화면 | 주요 요소 |
|---|---|---|
| SCR-01 | 로그인 | 이메일 로그인, 조직 선택 |
| SCR-02 | 홈/업무 템플릿 | 템플릿 카드, 실행 현황, 알림함 진입 |
| SCR-03 | 업무 실행 입력 | 템플릿 설명, 필수 입력, 실행 버튼 |
| SCR-04 | 실행 상세 | 실행 상태, 단계별 에이전트, 결과·오류 |
| SCR-05 | Google 연결 설정 | 연결 계정, OAuth scope 안내, 연결/해제, 자동 감지 on/off |
| SCR-06 | 일정 활동 내역 | 감지 메일 요약, 일정 제목·시간, Calendar 상태, 원본 메일 링크 |
| SCR-07 | 알림함 | 일정 등록·업무 완료 알림, 읽음 상태, 원본 메일 열기 |
| SCR-08 | 승인함 | 대기 항목, 결과 검토, 승인·반려 의견 |
| SCR-09 | 관리자 설정 | 사용자 역할, 템플릿/에이전트 버전 및 활성화 |

## 2. 일정 알림 상세

일정 활동 내역에는 원본 메일 제목, 발신자, 수신일시, 추출된 일정 시각과 timezone, Calendar 생성 결과를 표시한다. 이메일 본문은 기본 목록에 노출하지 않는다. 웹 푸시 클릭은 해당 Google 메일을 연다. 푸시 권한이 없으면 알림함에 같은 항목이 보이고 원본 메일 열기 동작을 제공한다.

## 3. 공통 화면 상태

각 데이터 화면은 loading, empty, error, permission denied 상태를 정의한다. 오래 걸리는 실행에는 취소 가능 여부와 마지막 갱신 시각을 표시한다. 키보드 포커스, 접근 가능한 이름, 충분한 대비를 보장하고 상태 색상만으로 정보를 전달하지 않는다.

## 부록 A. 상태 화면 디자인 가이드 — 구현 기준 (구 docs/harness/05_화면설계_가이드.md)

> 원본: `docs/harness/05_화면설계_가이드.md` (문서 버전 0.1, 기준일 2026-11-19). docs/harness/는 폐기되고 본 문서로 통합됨.

### 1. 디자인 방향

- **스타일**: 미니멀/스위스 — 그리드·여백 중심, 장식 최소, 고대비 텍스트.
- **색**: 단일 액센트 `#2563eb`(SaaS 블루). 상태색은 의미 있는 3색만
  (ok `#047857`, warn `#b45309`, err `#b91c1c`) — 모두 흰 배경에서 WCAG AA 충족.
- **타이포**: Fira Sans(본문) + Fira Code/시스템 모노(코드·ID). 제목 22px/600,
  섹션 라벨 13px uppercase + 자간.
- **배제**: 그라디언트, 그림자, glassmorphism, 네온, 보라-블루 AI 전형 그라데이션,
  이모지 장식.

### 2. 레이아웃

- 단일 컬럼 `max-width: 960px`, 좌우 24px 패딩 — 읽기 흐름이 한 줄.
- 섹션 순서: 헤더 → 새 실행 폼 → 실행 이력 테이블 → 실행 상세.
- 표는 `.table-scroll`로 가로 오버플로 처리(모바일 대응).

### 3. 상태 표현

- 상태는 **색 + 텍스트 배지 병행** — 색맹/저시력 대응.
- 배지는 pill 형태 + 상태별 테두리/텍스트 색(배경 채움 아님 — 미니멀 유지).
- 진행 피드백: 폼 제출 시 `role="status" aria-live="polite"`로 "제출 중…/실행 시작: id".
- 오류는 `err` 클래스 + 텍스트로 명시.

### 4. 접근성

- `:focus-visible` 아웃라인(액센트 2px), 키보드로 모든 인터랙션 가능.
- `prefers-reduced-motion` 대응 — transition 비활성화.
- 폼 레이블 연결(`for`/`id`), 버튼 텍스트 명확("승인"/"거부"/"상세").
- 의미 태그(header/section/h2/table) + aria-labelledby.

### 5. 상호작용

- 실행 이력 5초 자동 폴링(백그라운드 진행 상태 반영).
- 상세 패널: 단계 목록·승인 기록·PR 요약(details/summary 접이식)·승인/거부 버튼.
- 버튼 hover 160ms ease — 미세 전환만.

### 6. 확장 시 주의

- 새 화면도 동일 토큰(`:root` 변수)만 사용 — 임의 색/그림자 추가 금지.
- 다크모드는 후속(토큰 분리 시 대응). 현재는 라이트 단일.

## 부록 B. v2 Agent Office 화면설계 (2026-11-29 추가)

> 디자인 기준: `docs/UI_DESIGN_GUIDE.md`(미션 컨트롤 다크 테마).
> 목업 참조: `~/Downloads/am/*.png` — WorkMateBoard Agent Office 관제 스위트.
> 기능 스펙: `specs/010-dark-theme-shell/`, `specs/011-observability-modules/`.

### B.1 셸 구성

- **Global Header**(48~56px): 로고+제품명, 워크스페이스, 연결 상태
  표시등(SYSTEM ONLINE/DEGRADED/OFFLINE — SSE 연결·health 기반),
  수집 지연, 실시간 모드, 기간 선택, 검색, 알림, 설정, 프로필.
- **Left Sidebar**(200~220px): 메뉴 재배치(관제→관리→스윔→이력→도구→
  MCP→보안→비용→성능→보고→프로젝트→설정). 선택 메뉴 cyan+좌측 강조선.
  하단 인프라 박스: Collector/Backend/버전/CPU·Memory.
- **Inspector Panel**(우측 320~420px, 접이식): 선택 항목 상세.
- **Bottom Event Dock**(하단 180~240px, 접이식): 실시간 이벤트 로그.

### B.2 화면 목록 (v2)

| 화면 | 내용 | 데이터 소스 |
|---|---|---|
| 관제센터(office) | KPI 6~8+delta, Live Agents, Swarm 그래프, Security Radar, Throughput 차트, Event Stream, Execution Pipeline | /observability/* + /runs + SSE |
| 알림 대시보드 | 알림 KPI(긴급/중간/해결)+발생 추이+필터 테이블 | /observability/notifications |
| 에이전트 관리 | 온라인/오프라인 카운트+모델 태그 필터+상태 그리드 | /agents |
| 활동 로그 | 이벤트 타임라인+기간/에이전트/유형/키워드 필터 | audit/agent_session_events |
| 성능 분석 | 세션/성공률/응답시간/RPS+듀얼 차트+유형별 비중 | llm_stats |
| 작업·워크플로우 | 작업 KPI+퍼널+진행 중 카드 | /tasks + /observability/funnel |

### B.3 공통 규칙

- 색상은 토큰만 사용, 상태는 색+아이콘+텍스트 병행.
- KPI 숫자 `tabular-nums`, 실시간 목록 virtualization,
  차트는 ring buffer/다운샘플링.
- 데이터 없으면 Empty/"-"/"Not Configured" — 가짜 지표 금지.
- 모바일: sidebar/dock/inspector는 오버레이 시트.

### B.4 셸 컴포넌트·목업 리스킨 (spec 012~014, 2026-11-29 추가)

- **Inspector Panel**(우측 380px): run/trace/agent/session 선택 시 상세.
  팔레트·기능 뷰에서 `setInspector`로 오픈.
- **Bottom Event Dock**(하단 208px): SSE+external-logs 실시간 피드,
  터미널 스타일, 시크릿 마스킹.
- **Command Palette**(Cmd+K): 뷰/실행/세션/알림 검색·이동.
- **알림함**: KPI+추이+필터 테이블. **활동 로그**: 터미널 타임라인.
  **성능 분석**: KPI+듀얼 차트+모델 비중. **작업**: KPI+퍼널(lead)+
  진행 카드. **실행 이력**: status/days/q/agent 필터.
