## 1. 설계 원칙

- PK는 UUID, 모든 사용자 데이터는 organization 경계로 필터링한다.
- 저장 시각은 UTC, 사용자 입력 시간은 원본 timezone과 함께 보존한다.
- OAuth 토큰은 암호화 값으로 저장하고 모델 출력/메일 본문은 필요한 최소 기간만 보유한다.
- 상태 전이는 애플리케이션에서 검증하고 감사 이벤트를 남긴다.

## 3. 데이터 수명

Gmail 본문은 기본적으로 처리 메모리에서 사용하며 장기 저장하지 않는다. 처리에 필요한 요약·추출 필드와 Gmail message ID는 일정 추적 및 중복 방지를 위해 보관한다. 구체적인 보존 기간은 파일럿 조직 정책으로 설정한다. OAuth 연결 해제 시 토큰 삭제 및 관련 polling 중단, 푸시 구독 연결 해제를 수행한다. 이미 Calendar에 생성된 이벤트는 별도 사용자 요청 없이 삭제하지 않는다.

## 4. 멱등성·트랜잭션

Calendar 이벤트 생성 전 `calendar_event_links`에 `pending` 레코드를 원자적으로 확보한다. 생성 성공 시 `event_id`와 `created` 상태를 저장한다. 프로세스 장애 후 재실행은 같은 idempotency key를 사용하고 외부 이벤트 marker를 조회한다. 푸시 알림은 이벤트 링크 저장이 commit된 뒤 outbox/queue로 발행한다.
